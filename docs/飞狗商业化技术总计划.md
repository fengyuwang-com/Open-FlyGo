## 〇、核心结论（TL;DR，先看这节）

1. **软件本体已完成约七成**：面板运行中（8388）、控制面本机闭环（9001）、APK 1.0 debug 包已出、四类同步链路骨架（同步三步 UX / 互备编排 v1 / 引导页）已合 main。商业化缺的不是功能大件，而是**可售性补齐**。
2. **可售 = P0 去个人化 + 安装器 + 控制面上线 + 同步引擎落地 + APK 更新通道**，五件事，按顺序做，预计 6–10 周进入"可收钱内测"（首批 100 用户，M3 口径）。
3. **最大风险只有两个**：① 手机侧永远是"按需在线 + ROM 保活持久战"，一切承诺必须按此降级；② Windows 单机环境的长尾（Defender 误报、USB 插拔、开机自启）是售后成本主体，靠安装器 + 自检自愈 + 一键诊断包提前消化，不靠客服人肉。
4. **Freemium 红线不变**：本地功能永久免费，只有服务收费；expired 只停服务不停本地不停数据。本文所有设计都必须过这一条。

## 一、北极星：什么叫"能卖"

### 1.1 用户旅程验收（沿用 master-plan，一字不改）

> 新用户 30 分钟内完成"装面板 → 输 8 位激活码 → 数据汇聚 2 份副本"；心跳 5 分钟稳定；四类同步链路可走通；本地功能永久免费，只有服务收费。

商业化在北极星之外再加三条**可售验收**：

| # | 可售验收 | 含义 | 当前状态 |
|---|---|---|---|
| S1 | 裸机 30 分钟闭环 | 全新 Win10/11 电脑，无预装依赖，30 分钟内走完"装→激活→2 副本" | ❌ 未达（缺安装器；Docker/WSL/Tailscale/Syncthing 全靠手工） |
| S2 | 付费不断本地 | 订阅过期/控制面失联时，本地同步、文件访问、已有数据一切照常 | ✅ 架构已保证（节点自治），待 S3 联调时复验 |
| S3 | 售后不靠人肉 | 常见故障（Defender 拦截、USB 拔插、开机慢、同步停滞）用户按面板指引自助解决，客服只处理工单类问题 | 🔶 半达成（自检/自愈/守卫已落地，缺一键诊断包） |

## 三、商业化差距（Need：从现状到 S1/S2/S3 差什么）

### 3.1 P0 去个人化（用户 9-06 亲定，5 项，最高优先级）

在开发者机器上跑得好好的东西，到用户裸机上会逐个爆炸。5 项按爆炸顺序排：

| # | 个人化残留 | 用户机后果 | 改造方向 |
|---|---|---|---|
| D1 | `C:/` 等绝对路径写死 | 用户盘符/用户名不同直接崩 | install-root 相对化 + `detect_root()` 全覆盖审计 |
| D2 | `template-api` 引用本地镜像 | 用户机无镜像，应用功能全灭 | 模板镜像改为可拉取 registry 引用 + 国内加速源默认 |
| D3 | `CF_TOKEN / SESSION_SECRET / PASSWORD=admin` 明文 | 出厂弱口令 + 密钥入库风险 | 首启随机生成 + 落用户数据目录 + 绝不进 git（check-secrets 已有，扩展到新文件） |
| D4 | `control-plane/.env` 明文密钥 | 同上（服务端侧） | VPS 侧 env + 本地开发用 `.env.example`，真 `.env` gitignore |
| D5 | `base_url=http://127.0.0.1:9001` | 用户机连不上控制面，激活/心跳全灭 | base_url 可配置（安装器写入/VPS 上线后切公网）+ 控制面不可达降级（M15 已有，复验） |

### 3.2 安装器与首装体验（S1 的主体）

裸机装 FlyGo 今天需要手工：装 Docker Desktop（或 WSL2 + dockerd）、装 Tailscale 并登录、装 Syncthing、配面板、输激活码。**这不是产品，这是 DIY 套件**。安装器要做：

- 一键安装器（Windows）：捆面板 exe + 按需拉起 Docker/WSL2、Tailscale、Syncthing（能静默装的静默装，要点下一步的给向导页）。
- **组件下载系统**（用户已拍板方向）：面板自带 manifest（组件 → 版本 → 国内镜像 URL → sha256），缺什么下什么、装什么验什么。对外宣称"1 EXE + 1 APK"不变——安装器是交付壳，装完即走。
- 首启向导：装完自动开面板 → 激活码输入 → 汇聚目录选择（三步 UX 已有，直接复用 M06）→ 心跳上线 → 北极星闭环。

### 3.3 控制面上线（S1/S2 的计费前提）

DEPLOY-VPS 已就绪，动作全是用户侧 + 面板侧一小改：VPS 部署 → 面板 base_url 切公网 → 激活/心跳/订阅端到端复验（含控制面失联降级复验 S2）→ admin 签首批码。支付后置：激活码人工签发（已有），支付回调只留接口（技术计划已定，不做）。

### 3.4 同步引擎落地（S1 的"2 份副本"内核）

现状：Syncthing 是外部依赖（用户机可能没有），面板只在有 Syncthing 时才编排（M06/M07 经 REST 8384）。落地要求：

- Syncthing 必须成为安装器的**必装组件**（组件下载 manifest 第一项，版本 pinned + sha256 pinned，本轮原型已验证思路，正式实施时以本文 W-C4 规格为准）。
- daemon 托管：面板按需拉起 Syncthing（已有托盘托管经验，复用），8384 仅本机，REST 密钥运行时读。
- 验收：裸机装完 → 同步一个文件 → 2 副本；手机 send-only 汇聚验证（"节点删文件不反向删手机"）；staggered 默认开（M07 已有，复验）。

### 3.5 APK 更新通道（S1 的手机侧）

- release keystore（用户亲手）→ release 签名构建 → 官网/APK 下载页 → 面板内"手机接入"页给二维码。
- 更新通道：面板检测 APK 新版本（manifest 一项）→ 推送手机更新提示。首版可简陋（面板显示版本号 + 下载二维码），但必须有，否则每版靠用户口口相传。
- 真机三链路联调（用户亲手）：扫码配对 → send-only 汇聚 → 面板浏览，三链路按 flygo-app-plan §8 验收。

### 3.6 售后前置（S3：把客服成本杀在摇篮里）

- **一键诊断包**：面板"设置/关于"页一键导出（版本/自检结果/最近日志脱敏/磁盘/服务状态），用户贴给客服。日志脱敏规则与 check-secrets 同源。
- 自检页把 D1–D5 的运行时状态白盒化（base_url 通断、Syncthing 存活、磁盘空间、Defender 豁免提示）。
- Defender 误报（`Bearfoos.A!ml`，本轮已建档 `docs/defender-false-positive.md`）：短期白名单指引进安装器/首启向导；长期代码签名证书（需采购，用户决策）或微软申诉（每版一次）。

## 五、模块设计（P0 六个模块：做什么/选型/验收）

### 5.1 去个人化（W-C1，对应 D1–D5）

- **D1 路径相对化**：全仓审计写死绝对路径（`C:/`、`C:\FengNAS`、`C:\FengProj`），收敛到 `detect_root()` + 相对路径；`config/` 继续 gitignore；测试里加一条"全仓无新增硬编码路径"断言（grep 门）。
- **D2 模板镜像 registry 化**：`template-api` 本地镜像引用改为 registry 可拉取引用；docker 拉取默认走国内加速源（已有国内镜像铁律，落到 compose 模板层）；无加速源时降级提示人话。
- **D3/D4 密钥治理**：首启随机生成 SESSION_SECRET/初始密码（密码首启向导强制改，`PASSWORD=admin` 只允许首启一次性）；`control-plane/.env` 进 gitignore，加 `.env.example`；check-secrets.sh 覆盖新文件类型。
- **D5 base_url 可配置**：面板设置（文件 + 环境变量 `FENGPAGE_CONTROL_BASE`）→ 安装器写入 VPS 地址；默认仍本机（开发零影响）；控制面不可达降级复验（M15 逻辑 + 新 base_url）。
- 验收：全新 Windows 虚拟机（无开发者痕迹）跑安装器，全程无"找不到 C:/xxx"类错误；`git status` 无密钥文件。

### 5.2 安装器 + 组件下载系统（W-C2/W-C3，S1 主体）

- **安装器形态**：Windows 安装向导（技术选型二选一，实施前拍板：① NSIS 脚本——轻、免费、可定制；② 直接用面板 exe 自带 `--install` 自解压模式——零新依赖，复用 Rust 单文件哲学，推荐但需验证 UAC/卸载语义）。无论哪种：装完只有一个面板 exe 常驻 + 托盘，Docker/Tailscale/Syncthing 以组件形态存在。
- **组件下载系统**（用户已拍板，规格如下；本轮原型作废重做，只收编思路）：
  - manifest（JSON，随面板发版，可热更新 URL）：`[{id, kind: file|archive|msi|image, version, urls[国内优先], sha256, target, required}]`。
  - 首批组件：syncthing（archive，**版本+sha256 双 pinned**，required）、tailscale（msi，签名即信任锚，required）、docker-desktop/WSL2 内核（引导安装，required）、flygo-mobile apk（file，FENGPAGE_APK_URL 配置，optional）。
  - 流程：缺失检测（自检页）→ 一键补齐（逐个下载→sha256 校验→安装→复检）→ 失败人话（哪个镜像站超时、换哪个源）。
  - 安全：sha256 不匹配拒绝安装并删除；msi 只认 Authenticode 签名；安装目标只允许 manifest 白名单路径（防路径穿越）。
- 验收：裸机（快照虚拟机）从零到面板首页 ≤30 分钟；断网换源/杀进程重入不残留半装状态。

### 5.3 控制面上线（W-C5，计费前提）

- 用户侧：VPS（2C2G）→ DEPLOY-VPS.md 走一遍 → DNS → HTTPS。
- 面板侧：base_url 切公网（5.1 已做可配置）→ register/activate/heartbeat/status 全链路复验 → 控制面失联降级复验（S2：拔网线，本地同步/文件访问照常，心跳补报）。
- 运营侧：admin 签首批试用码 → 北极星脚本 live 模式跑通（M16 live 环节依赖真机，见 5.5）。
- 验收：公网激活一台新节点，心跳 5 分钟稳定；控制面停机 1 小时，节点本地功能零影响（S2 铁证）。

### 5.4 同步引擎落地（W-C4，含前置研究）

- **前置研究（先做，1 周）**：把 Syncthing 研究透——REST API 全量（8384）、staggered 参数、send-only 语义边界、`.stignore` 最佳实践、多设备配对坑、版本升级兼容。输出 `docs/syncthing-deep-dive.md`，再动手。
- 实施：Syncthing 进组件 manifest（必装）→ daemon 按需托管（复用托盘托管模型 + CREATE_NO_WINDOW 安静原则）→ 8384 本机绑定 → M06/M07 编排层复验（不动编排逻辑，只换引擎来源）。
- 验收：裸机 2 副本闭环；"节点删文件不反向删手机"；staggered 误删回滚演示一次（录屏存档，客服素材）。

### 5.5 APK 更新通道（W-C6，手机侧 S1）
