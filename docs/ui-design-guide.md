# FlyGo UI 设计宪法（ui-design-guide）

> 本文档是 FlyGo 面板（`panel/static/index.html`，单文件前端）的 UI 设计指导文件。
> 来源：提炼自 `~/fengyuwang_com/DESIGN.md`（个人站设计规范）的**可迁移灵魂原则**，并按"工具型控制面板"（非营销站）做适配。
> 状态：v1.0，2026-08-16。配套审计报告见 `ui-audit-report.md`。
> 冲突仲裁：本文档与任何单次实现冲突时，以本文档为准；本文档与代码现状冲突时，以本文档为准（现状问题见审计报告）。

## 0. 灵魂从哪里来、怎么适配

| 源站（营销型个人站） | 灵魂 | FlyGo 适配 |
|---|---|---|
| 理性 · 客观 · 不坑人，不卖自己 | 文案调性 | **保留原样**：面板文案不邀功、不说教、不喊"强大"；给真实预期（时长、阈值、后果） |
| 白空间是特性（12px 签名间隙） | 间距即呼吸 | 面板内卡片间距统一为刻度，间隙是特性不是浪费 |
| Frosted over solid（backdrop-filter 半透明，不用不透明填充） | 覆盖层毛玻璃 | 模态覆盖层（重启遮罩等）用半透明+blur；普通卡片仍实色（工具型信息密度高，实色可读性优先） |
| 冷色调 slate + 单一蓝色强调，无暖色、无第二强调色 | 色彩纪律 | **保留原样**：语义色（绿/黄/红）只做状态指示，绝不进入品牌元素 |
| 字重纪律：强调来自颜色和笔画，非字重；无斜体 | 排版纪律 | **保留原样**：字重分层固定，不堆 bold |
| 字体比例纪律、卡片字体冻结值 | 排版刻度 | **保留原样**：字号刻度表 + 卡片字号冻结 |
| 深色模式逐元素显式覆盖，无全局 fallback | 主题纪律 | 用 CSS 变量实现"两套显式值"，新增元素必须两主题都定义 |
| CSS 无魔法数字 | 代码纪律 | 间距/圆角/字号全部进刻度表 |
| 一页一思想锚点 | 信息架构 | **适配**：一视图一焦点（每个视图一个主任务，不堆无关功能） |
| punchline 标题 | 标题风格 | **适配**：视图标题/区块标题一句话说清本区块是干什么的（允许直白） |
| 一次性特效必须显式申请（风暴辉光） | 特效纪律 | **保留原样**：任何一次性动画/特效须在本文档 §10 登记才能进代码 |
| hero slider / 预加载动画 / 三语言 hreflang / 博客 TOC / 艺术页暖色例外 / 品牌元标签 | 营销站特有 | **不迁移** |

### 0.1 不采用：个人网站专属元素（排除清单）

以下元素来自个人网站的场景，FlyGo 面板**一律不采用**（改动审计时遇此即删/不引入）：

- **个人署名与签名间隙**（"Feng 2026"、页脚个人版权）——面板页脚是产品名 + 版本号
- **hero 首屏**：大图、自我简介、大号标题 + 副标题结构——面板首页是功能总览
- **社交名片**：GitHub/微信/邮箱链接墙、"联系我"区块
- **博客排版**：文章卡片、TOC、时间线、散文式段落、代码高亮块——面板没有内容发布场景
- **艺术页例外**：暖色放飞、实验性布局、无网格排版——面板全站语义色纪律生效，无例外页
- **非系统字体**：衬线体、手写体、品牌字体——面板只用系统 UI 字体栈（§4.1）
- **源站一次性特效复刻**：风暴辉光等纯展示型特效——不复制源站花活

### 0.2 要搞上去：导航元素与动效（实用属性优先）

以下元素**不是**"个人网站专属"，按实用属性验收，好理解、好用：

- **下拉菜单**：用于操作分组收纳（如顶栏"更多"收起低频操作、托盘级菜单）。验收：一级可见的操作不加层级；菜单项文案即操作名，不玩命名花样。
- **面包屑**：用于层级定位（有父子页面的视图，如 同步网络 → 设备详情）。验收：不超过 3 级；与侧栏导航状态同步，不重复造导航。
- **语言切换**：中文为主，保留 i18n 扩展（官网/手机端先行）。验收：切换即时生效、不刷新丢状态。
- **SEO/OG 元标签**：**官网场景**（flygo.fengyuwang.com）必须——标题/描述/OG 图/结构化数据；面板本地工具不做 SEO。
- **装饰性动效**：允许且鼓励**过渡与反馈动效**——视图切换淡入（120~200ms）、hover 反馈、状态变化过渡。验收：动效必须有功能意义（解释状态变化/引导视线/确认操作结果），**纯装饰无信息价值的不加**；滚动渐入、鼠标跟随、hero slider、预加载动画等营销式花活不采用；所有动效进特效登记表。

总原则：**导航与动效服务于"更快找到、更清楚发生了什么"，不是服务于好看**。任何元素引入前过一遍："它让用户更好理解或更好用了吗？"——答不上来就不加。

判定标准：**源站是"给人看的站"，面板是"给人用的工具"**。凡元素的存在理由是"展示/营销/个人表达"而非"操作/状态/信息密度"，即不采用。灵魂只取五样：理性文案、冷 slate+单蓝、字重字号纪律、深色显式覆盖、一视图一焦点。

## 1. 设计原则（8 条）

1. **理性客观，不坑人。** 文案只说事实和操作后果，不自夸、不说教、不卖弄。给用户真实的预期：时长、阈值、失败原因、影响范围。宁说"约 5~10 秒"，不说"秒开"。
2. **一视图一焦点。** 12 个视图各有唯一主任务。一个视图不塞两个无关的活儿；辅助说明放 `<span class="sub">` 或折叠区。
3. **白空间是特性。** 面板用统一的间距刻度制造呼吸感；卡片之间留白不是浪费。不要用不断加边框/加深背景来区分层级。
4. **冷色调 + 单一蓝色强调。** 系统只有 slate 灰蓝 + 一个强调蓝。暖色（橙/红/黄/绿）只作为语义色出现，且**只**用于状态指示，绝不用于品牌、按钮主色、高亮装饰。
5. **强调来自颜色和笔画，不来自字重。** 层级用颜色（accent / muted）、边框、圆点表达；body 文案一律 400，不靠加粗制造强调。无斜体。
6. **纪律优于便利。** 字号、间距、圆角、阴影全部从刻度表取值。宁可少一个档位，不临时发明新值。需要新值 = 先改刻度表（集体决策），不是加一行 CSS。
7. **主题是两套显式值，不是补丁。** 深色/浅色由 CSS 变量在主题根上一次性定义；任何颜色、阴影、边框必须走变量。禁止裸 `#fff`/`#000` 硬编码（功能例外需注释，见 §8）。
8. **状态要可感知、可预期。** 任何异步加载区必须有三态：加载中（有预期时长文案）→ 空态（说明"是什么 + 怎么开始"）→ 错误态（原因 + 怎么办）。危险操作必须 confirm 并写明后果。

## 2. 文案调性（工具型面板专属）

### 2.1 规则

- **不用第二人称**："你可以""你只需""方便你…" 一律禁止。操作指引用祈使句（"点「停用」即关闭自启"），状态描述用陈述句。
- **不自夸**：禁"强大/极致/完美/领先/最好"。功能描述只写它能做什么。
- **给真实预期**：凡有时长的操作写时长（"冷启动约需 30~60 秒"）；有阈值的写阈值（"<200ms 绿 / <1000ms 黄 / 超时红"）。
- **说后果**：危险操作在 confirm/说明里写清楚影响范围（"会断开所有远程 SMB 连接并对 USB 断电"）。
- **错误态给"原因 + 怎么办"**，不止"失败"两个字。
- **空态给"是什么 + 怎么开始"**，不止"暂无数据"。
- **少说教**：不做价值判断（"你应该…"），只陈述机制（"手机不是服务器，前台同步最快"）。

### 2.2 文案调性检查表（写任何 UI 文案前过一遍）

- [ ] 有没有"你/您"？有 → 改祈使句或陈述句
- [ ] 有没有自夸形容词（强大/极致/完美/最新）？有 → 删
- [ ] 有没有"高效/流畅/安全"这类无数字的空话？有 → 换成数字或删掉
- [ ] 异步操作有没有预期时长？没有 → 补
- [ ] 危险操作有没有后果说明？没有 → 补
- [ ] 错误态有没有"原因 + 怎么办"？没有 → 补
- [ ] 空态有没有"怎么开始"？没有 → 补
- [ ] 有没有感叹号堆砌 / emoji 与文字抢注意力？有 → 收敛（emoji 一个区块至多一个）
- [ ] 状态词是否全站统一（运行中/已停止/在线/离线…）？不统一 → 对齐

## 3. 色彩系统

### 3.1 主色板（token 化，现状已基本达标，见 §3.3 增量）

| Token | Light | Dark | 职责 |
|---|---|---|---|
| `--bg` | `#f3f5f8` | `#0f1115` | 页面底（冷灰蓝，非纯白纯黑） |
| `--panel` | `#ffffff` | `#15181e` | 一级卡片/导航底 |
| `--panel2` | `#f0f2f6` | `#1a1e26` | 二级卡片/内嵌块/悬浮底 |
| `--border` | `#dbe0ea` | `#262c36` | 所有 1px 描边（hairline，不用阴影代替边框） |
| `--text` | `#1a2433` | `#e5e7eb` | 主文本 |
| `--muted` | `#5b6b80` | `#8b93a1` | 次文本/说明/占位 |
| `--accent` | `#2563eb` | `#4c9aff` | **唯一**强调蓝：主按钮、焦点、选中、进度、链接 hover |
| `--accent-bg` | `#e3ecfb` | `#20314a` | 强调蓝的浅底（选中导航、徽章底） |
| `--bar-bg` | `#e4e8ef` | `#101419` | 进度条轨道 |
| `--ov-bg` | `rgba(243,245,248,.93)` | `rgba(15,17,21,.93)` | 覆盖层底（建议加 blur，见 §3.4） |

### 3.2 语义色（唯一职责 = 状态指示）

| Token | Light | Dark | 用途（只允许这些） |
|---|---|---|---|
| `--ok` | `#059669` | `#34d399` | 状态点/灯、成功消息、"已同步" |
| `--warn` | `#d97706` | `#f59e0b` | 警告状态、同步中、进度 <100% 的进度条 |
| `--err` | `#dc2626` | `#ef4444` | 错误状态、危险按钮、掉线告警、`ac-warn` 警示卡 |

规则：

- 绿/黄/红**只能**出现在：状态点（`i.ldot`、`.tile i`）、状态文本（`.ok/.err` 类）、进度条（`.bar>div`）、警告卡（`.ac-warn`）、危险按钮（`.btn.danger` 文字+底）。
- 语义色**不允许**出现在：品牌、导航选中、普通按钮主色、链接、卡片边框、装饰。
- 灰色状态点（未映射/离线）用 `--border` 系或专用 `--dot-gray`，不许再发明第四个语义色。

### 3.3 与现状的增量（不推翻现有变量，只补齐）

现状（index.html L9-20）已满足骨架，需补齐：

- `--dot-gray`：状态点灰 `#555` 硬编码（L46、L89）抽成变量（建议 light `#9aa3b2` / dark `#565d6a`）。
- `--shadow-sm` / `--shadow-md`：卡片阴影 token 化（现状 `0 1px 2px rgba(0,0,0,.15)` 硬编码在 `.tile` L44、`.swcard` L83，浅色主题下偏重）。
- `--bar-warn` 不必新建：`.warn .bar>div` 直接复用 `--warn`。

### 3.4 覆盖层毛玻璃（frosted over solid 的适配）

- `--ov-bg` 是唯一允许"半透明大色块"的地方（重启遮罩 L139、iframe 覆盖层可复用）。
- 建议：`.restart-ov` 加 `backdrop-filter: blur(20px) saturate(180%)`（有 webkit 前缀），半透明底 + blur，避免生硬的深色板子。保留 `--ov-bg` 作为降级。
- 日常卡片**不**做毛玻璃：工具型面板信息密度高，实色可读性优先。毛玻璃只用于"盖在动态内容上"的场景。

### 3.5 禁止

- 禁止第二强调色（现状没有，保持）。新增任何彩色先问：它是状态吗？不是 → 用强调蓝或 slate。
- 禁止暖色出现在非语义位置（现状 emoji 自带彩色是最大隐患，见审计 P1-3）。
- 禁止纯 `#fff` 大面积背景块（浅色主题 panel 是 `#ffffff`，这是页面卡底色，允许；但不要再往深色主题里塞 `#fff` 块）。

## 4. 排版

### 4.1 字体栈（现状 L22 缺中文字体）

现状：`-apple-system,BlinkMacSystemFont,'Segoe UI',Roboto,'Helvetica Neue',sans-serif`

Windows 上 `Segoe UI` 不含中文字形，中文会落到系统默认（微软雅黑），实际渲染 OK 但不可控。建议：

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI",
  "Microsoft YaHei", "PingFang SC", "Noto Sans SC",
  "Helvetica Neue", Roboto, Arial, sans-serif;
```

- 不加斜体（`font-style: italic` 全站禁用）。
- 不引入 web 字体（面板要离线可用、秒开，系统字体栈足够）。

### 4.2 字号刻度表（rem 基准，16px）

| 档位 | 值 | 用途 |
|---|---|---|
| S4 | `.64rem` | 卡片内元信息（`.svc .d`、`.swcard .m`）——现状值保留 |
| S3 | `.68rem` | 说明文字（`.metric .lab`、`.log`、`.foot`、`.dim` 小字） |
| S2 | `.75rem` | 区块说明/表单标签（`.ac-lab`、提示行） |
| S1 | `.8rem` | **正文档**：导航项、行内容、按钮、卡片标题（`.navi`、`.row`、`.btn`、`.phead`） |
| S0 | `.9rem` | 强调块文字、`.phead` 标题可上浮到这档 |
| T1 | `1.05rem` | 视图标题（`.top .h1`） |
| T2 | `1.15rem` | 大数值（`.metric .val` 可上浮到这档） |

**冻结规则（借鉴源站"卡片字体冻结值"）**：

- `.btn` = S1，`.phead` = S1，`.metric .lab` = S3，`.tile` = S1。
- 不许在冻结档位上加"我这次大一点"：网格节奏靠刻度保证。
- 现状零散值（`.66/.7/.72/.78/.82/.85/.95/1.05/1.15rem` 等 15 档）逐步收敛到上表 8 档，收敛期间新代码只许用表内值。

### 4.3 字重纪律（现状 400/500/600/700 混用，收敛为 3 档）

| 字重 | 用途 |
|---|---|
| 400 | 一切正文、说明、链接、行内容 |
| 500 | 中等强调：导航项、行名称 `.rn`、卡片标题（现状大量 500/600 可归此档） |
| 600 | 组件级强调：按钮文字、`.phead` 标题、`metric .val` 数值 |

- 禁止 700/800/900（现状 `.brand .logo` 700 可改 600）。强调靠 `--accent` 颜色和 500/600 档，不靠粗体堆叠。
- 无斜体；无全大写拉伸。

## 5. 间距与圆角

### 5.1 间距刻度（4 基制）

| Token | 值 | 用途 |
|---|---|---|
| S-1 | `.25rem` (4px) | 图标与文字微距 |
| S0 | `.4rem` (6px) | 紧凑元素内距/小 gap |
| S1 | `.55rem` (9px) | 卡片内距、常规 gap |
| S2 | `.7rem` (11px) | 面板间距（现状 `panel margin-bottom .7rem` ≈ 源站 12px 签名间隙，保留） |
| S3 | `1rem` (16px) | 区块间、main 内边距 |
| S4 | `1.4rem` (22px) | 大区块间距 |

- 现状散乱值（`.42/.45/.5/.6/.65/.72/.75/.8/.85/.9/.95/1.05/1.1/1.3/1.5rem`）逐步收敛；新代码只许用表内值。
- 不用 px 做间距（现状基本是 rem，保持）；固定容器尺寸（nav 宽、行名宽）除外，见 §5.3。

### 5.2 圆角刻度（收敛现状 6/7/8/9/10/12 六档为三档）

| 档 | 值 | 用途 |
|---|---|---|
| R1 | 6px | 控件：按钮、输入框、logo 小块 |
| R2 | 8px | 内嵌小卡：`.metric`、`.svc`、`.pstep` |
| R3 | 10px | 面板/大卡/浮层：`.panel`、`.tile`、`.swcard`、`.snf`、`.qrbox`、`.mmenu` |

- 圆角大档位（18/24/32px 那种营销感圆角）不进面板；工具型 UI 用 6/8/10 保持利落。
- 现状 `.mmenu` 12px、`.brand .logo` 7px 分别并入 R3/R1。

### 5.3 固定容器尺寸（允许 px 的少数例外，须有注释）

- `nav` 宽 `168px`、`.rn` 宽 `108px`、`.tile` 高 `58px`、`.qrbox` `232px`、顶栏高 `52px`——这些是**结构性**固定值，允许，但每个都要注释用途，不许再新增同类魔法数。

### 5.4 阴影规范

| 档 | 值 | 用途 |
|---|---|---|
| 平 | `0 1px 0 var(--border)` | 分隔 hairline（代替粗边框） |
| 轻 | `0 1px 2px rgba(15,23,42,.08)` | 卡片常态（现状 `.15` 偏重，建议降） |
| 浮 | `0 10px 30px rgba(15,23,42,.2)` | 浮层（`.mmenu`、覆盖层） |

- 深色主题下阴影自动减重（`rgba(0,0,0,.4)` 上限），走 `--shadow-*` 变量两套值。
- 不用"边框+重阴影"叠加制造层级，二选一。

## 6. 组件规范

### 6.1 按钮（`.btn`）

- 主操作：`.btn.on` = `--accent` 底 + 白字（`--text-on-accent` 建议抽变量）。
- 次操作：`.btn.off` = `--panel2` 底 + `--muted` 字 + `--border` 描边。
- 危险：`.btn.danger` = `--err` 底 + 白字，**仅**用于破坏性操作（删除规则、退出全部后台、弹出磁盘）。
- 禁用：`opacity .4` + `cursor:not-allowed`（现状 L102，保留）。
- 尺寸：桌面 `padding .28rem .6rem` 保持；移动端 min-height 40px（现状 L234，保留，这是触摸目标纪律）。
- 文字：动词开头（"启动/停止/删除/刷新"），不加感叹号；emoji 前缀至多一个且与动词语义相关（现状 🚀↗🔁 等可保留但全站对齐）。
- 不允许按钮承担"主色以外的强调"：全站只有 accent 蓝和 err 红两种按钮底。

### 6.2 卡片

- 信息卡 `.panel`：白/深面板底 + 1px `--border` + R3 圆角；内部标题用 `.phead`（S1 字重 600 + `.sub` 灰色副题）。
- 服务卡/状态卡 `.swcard` / `.svc`：`--panel2` 底，整卡可点（`cursor:pointer` + hover 描边 accent，现状 L83-84 保留）；状态表达只用 `.ldot` 圆点 + 状态文字，不许给卡片整体染色。
- 指标卡 `.metric`：标签 S3 灰 + 数值 T1 600 字重；进度条 `.bar` 高 5px R99。
- 新增卡片类型前：先看能否用 `.panel` / `.metric` / `.svc` / `.swcard` / `.snf` 五种现有卡组合出来（借鉴源站"五种卡类型，不发明第六种"）。

### 6.3 状态灯（全站统一，现状有三种点，收敛为一种）

- **统一用 CSS 圆点**（`width:8px;height:8px;border-radius:50%`），颜色 = 语义色：
  - 绿 = 运行/在线/已同步；红 = 停止/离线/错误；黄 = 中间态（同步中/降级）；灰 = 未知/未映射（`--dot-gray`）。
- 现状三种表达（`.tile i` 8px 圆点、`.ldot` 8px 圆点、tray/phone 行内 `●`/`○` 文本字符 L1242/L1248/L1253/L1338）→ 收敛成一种。`●` 字符在浅色下渲染成色块、粗细随字体，与 CSS 圆点视觉不一致。
- 灯旁边必须有文字标签（"Syncthing/Tailscale/SSH"），不许只有色点。

### 6.4 表单

- 输入框 `.tinput`：`--panel2` 底 + `--border` 描边 + focus 变 `--accent`（现状 L183-184 保留）。
- 标签：`.ac-lab`（S2 灰 600）为全站表单标签样式；终端改密表单目前用 placeholder 代替标签（L388-390），允许但同一表单内保持一致。
- 单选/复选：`accent-color: var(--accent)`（现状 L191 保留）。
- 校验：行内错误消息统一 `.err` 红色文字（现状 L1042-1044 达标）；消息区预留固定位置，不要闪烁。
- 危险选项（"所有人"开放端口）：必须内联警示卡 + 显式确认勾选（现状 `.ac-warn` + confirm 勾选，达标，保持）。

### 6.5 导航

- 侧栏 `.navi`：S1 字号、emoji 统一占宽（现状 `em{width:1.4em}` L35，保留——这是好机制）、选中态 = `--accent-bg` 底 + `--text` 字 + 600 字重（现状 L32 达标）。
- 顶栏 `.tiles`（服务入口区）：7 项等宽等高网格（`repeat(7,minmax(0,1fr))` + `min-height:58px`，现状达标）；**仅总览视图显示**（现状全视图共享，见审计 P1-1）。
- 移动端：899px 断点 + `.hbar` 固定顶栏 + `.mmenu` 下拉（现状达标）；`.mmenu` 阴影按 §5.4 走变量。

### 6.6 表格/列表

- 行式列表 `.row`：`.rn`（名称，左）+ 弹性内容 + `.rinfo`（右对齐灰色详情），底部 hairline 分隔（现状 L66-71 达标）。
- 行内状态词全站统一：运行中/已停止/在线/离线/已同步/同步中/未运行/已启用/停用。
- 长内容：路径/命令一律 `pre + word-break:break-all + overflow-wrap:anywhere`（现状已普遍应用，保持）。

### 6.7 三态（加载/空/错误）

| 态 | 要求 | 现状示例（达标） |
|---|---|---|
| 加载中 | 有明确预期时长文案 + spinner（`.spin`） | "正在启动（冷启动约需 30~60 秒）…" L364 |
| 空态 | 说明"是什么 + 怎么开始" | "尚未配对任何设备——完成第 2 步扫码后这里会出现手机。" L1337 |
| 错误态 | "原因 + 怎么办"，有操作出口（重试/打开/去某页） | "服务已运行，但端口访问不通（可能是端口转发问题）"+ "在新标签页打开" L688 |

- 禁止只有"加载失败/失败"两个字的错误态（现状 L832/L877/L890 违规，见审计 P1-6）。

## 7. 深色模式规则

1. **两套显式值**：所有颜色 token 必须在 `[data-theme="dark"]` 和 `[data-theme="light"]` 两个根块里**都**定义（现状 L9-20 已做到）。新增元素不许只写一套值。
2. **无全局 fallback**：不写 `body[data-theme="dark"] h1{...}` 式的兜底——那会掩盖漏网，让新元素在暗色下静默变黑。漏网靠变量机制杜绝：引用未定义变量 = 显式报错（开发期可查）。
3. **禁止裸 `#fff`/`#000`**。功能例外必须注释（现状已有三个正确例子）：
   - `.qrbox` 白底（二维码需要，L170）；
   - `#term-host` 恒黑底（终端需要，L196-201，有注释）；
   - 全屏态 `#0b0e14`（全屏媒体背景，L147/L150）。
4. **阴影两套**：浅色阴影（黑 alpha 低）+ 深色阴影（黑 alpha 高但不超过 `.4`），走 `--shadow-*`。
5. **新增组件 checklist**：底色/文字色/描边/阴影 四项在 light 和 dark 各看一眼，再提交。
