## 0. 一句话定位

> **Syncthing 管"自动汇聚"（照片/下载目录定期上传），PlainApp 管"即时取用"（想拿哪个文件，浏览器直连手机拿）——两条互补链路，手机既是汇聚客户端，又是移动网盘。**

| 链路 | 工具 | 方向 | 时机 | 定位 |
|---|---|---|---|---|
| 自动汇聚 | Syncthing-Fork（send-only） | 手机 → 节点 | 后台持续 | 照片/视频/下载目录自动备份 |
| 即时取用 | **PlainApp Web 服务** | 双向（浏览/下载/上传） | 按需打开 | 任意文件随手拉取、随手塞回 |

## 1. 场景与用户故事（1TB 手机 = 移动网盘）

**主场景**：用户的安卓手机（1TB 容量）平时带在身边，等于随身携带 1TB 移动硬盘。电脑（家里台式机 / 笔记本）需要某个手机里的文件时：

1. 手机上打开 PlainApp →「发射」Web 服务（点亮一个开关的功夫）；
2. 电脑浏览器输入手机地址（Tailscale IP:端口，或局域网 IP:端口）；
3. 浏览手机存储 → 下载要的文件 / 拖文件上传 → 关掉。

**为什么这个场景成立**（用户已实测）：
- PlainApp 最新版在安卓 16 上工作正常，"发射/Web 服务器"功能可用；
- 手机 1TB 容量远超电脑/节点可用空间——手机就是最大的"冷存储 + 随身存储"；
- Tailscale 已铺好（节点 100.101.102.103），手机装 Tailscale App 即入网，地址恒定、加密、跨网络可达（在家走局域网，出门走 DERP/中继）。

**手机 vs 节点的角色边界**（沿用技术计划"手机不当真节点"结论）：
- 手机**不**承担节点职责（无 Docker/转码/7×24 服务承诺）；
- 手机提供的是**按需在线**的"文件服务端点"：人在手机旁（或手机有电有网）时可用；
- 关键数据仍以"汇聚到节点 + 节点互备"为准，PlainApp 是**取用通道**，不是备份通道。

### 2.1 能力清单（Web 服务功能提供什么）

**已核实（README Features 表）**：浏览器打开即得完整手机管理面板，电脑侧零安装、支持 PWA：

| 能力 | 说明 |

## 3. 整合方案设计

### 3.1 拓扑

```
┌──────────────┐   Tailscale 100.64.0.0/10（加密 P2P）   ┌──────────────┐
│  FlyGo 节点   │ ◄────────────────────────────────────► │  安卓手机      │
│  (Win 电脑)   │   面板 8388 / Syncthing 8384             │  PlainApp     │
│  面板+卡片墙   │   节点侧探手机: <手机TS-IP>:<端口> TCP     │  发射 Web 服务 │
└──────────────┘                                          └──────────────┘
        │ 局域网 192.168.1.x（同 WiFi 时可选直连）
        ▼
  浏览器/其他设备 —— 直接访问 http://<手机IP>:<端口>（浏览/下载/上传）
```

- **两条访问路径**：Tailscale（跨网络，恒定地址，加密）为默认；局域网（同 WiFi，低延迟，速度快）为备选。PlainApp 服务本身无鉴权（或弱鉴权）时，两条路径都依赖"网络层信任边界"——见 §5 安全。
- **节点面板的角色**：不代理流量（数据平面保持 P2P 直连，符合"控制面不碰数据"原则），只做**登记 + 探测 + 直达链接**。

### 3.2 手机接入引导页（onboarding）— PlainApp 区块

> 复用并行任务正在做的 onboarding 引导页（`/api/onboarding/*` + 前端"手机接入"页），在其中**新增 PlainApp 引导区块**，与 Syncthing 扫码配对并列。

**引导流程（三步可达，符合产品哲学"三步可达"）**：

| 步骤 | 内容 | 复用点 |
|---|---|---|
| ① 下载安装 | 显示 PlainApp 下载二维码/链接（GitHub Release，国内镜像说明）+ 安装后授予存储权限 | onboarding 已有 `?text=` 二维码渲染接口（下载链接直接出 QR） |
| ② 打开发射 | 图文/短视频式指引：打开 App →「发射」→ 启动 Web 服务器，显示手机侧地址 | 新文案区块 |
| ③ 得到地址 | 面板显示手机两种地址（Tailscale IP:端口 / 局域网 IP:端口）+「添加手机节点」按钮（写入面板配置） | 新交互，见 §4 |

**保活清单折叠区**：沿用 onboarding 已设计的"安卓分厂商保活设置"清单结构，PlainApp 区块复用同一折叠组件，条目为 PlainApp 专属（见 §6）。

### 3.3 服务卡片墙 / 总览 —「手机节点」卡片

- **位置**：总览页"服务状态"卡片墙（svcwall）**追加一节"手机节点"**，或复用图标网格区（overview 图标区已改为等宽等高网格瓦片，天然适合放手机卡片）。
- **卡片内容**：
  - 名称：手机节点（可自定义，如"Feng-Phone"）；
  - 状态灯：绿/黄/红——**TCP 探测手机地址:端口**（复用 `health.rs` 的 `probe_tcp` 模式，探测目标从 127.0.0.1 改为手机 IP；超时 3s 不变）；
  - 地址行：Tailscale IP:端口 + 局域网 IP:端口（若两个都登记）；
  - 点击行为：`window.open(http://<手机IP>:<端口>)` 新标签直达手机 Web 服务（与现有服务卡片一致）；
  - 附注：显示"按需在线"提示（手机不在线 = 正常状态，红/灰灯不报错，区别于节点服务故障）。
- **刷新节奏**：与 svcwall 一致（15s），探测成本零（单 TCP connect）。

### 3.4 控制面 / 设备清单角度

- 手机作为**"汇聚客户端 / 移动网盘节点"**登记进控制面设备清单（阶段：W2 面板接入控制面已有设备注册基础）：
  - 设备类型字段扩展：`phone_gather`（汇聚客户端）或 `phone_drive`（移动网盘）；
  - 登记内容：设备 ID（Syncthing device ID 复用）、Tailscale IP（可选）、PlainApp 端口（可选）、容量（1TB）、最后心跳时间；
  - 控制面只收**元数据**（类型/IP/端口/容量/心跳），不收文件路径与内容——符合遥测隐私边界（技术计划风险 3）。
- MVP 说明：手机侧**不装飞狗任何代码**，登记由**电脑侧面板引导**完成（用户在引导页点"添加手机节点"→ 面板把信息上报控制面）。手机本身零改造——这正符合"1 个 EXE + 1 个 APK"哲学里"APK 由现成 App 拼装"的降级形态。

### 3.5 文件双向传输可行性

**PlainApp 网页端支持上传/下载（用户已实测可用）→ 双向传输成立**：

| 方向 | 操作 | 场景 |
|---|---|---|
| 手机 → 电脑 | 浏览器打开手机服务 → 下载文件 | 拉取手机里的大文件/照片/文档 |
| 电脑 → 手机 | 浏览器拖文件上传 → 手机多一份副本 | 把电脑文件塞进手机 1TB（异地容灾副本、随身携带） |

**与 Syncthing 的互补定位（关键设计，别混用）**：

| 维度 | Syncthing-Fork（自动） | PlainApp（手动） |
|---|---|---|
| 触发 | 后台持续、按目录规则 | 人肉按需、任意文件 |
| 方向 | send-only（手机 → 节点） | 双向（谁在浏览器谁做主） |
| 适用 | 相册/下载目录等"长期自动备份" | 一次性取用、临时塞文件 |
| 一致性 | 双向设备配置 + 版本控制 | 无一致性概念（直接读写手机文件系统） |
| 风险 | 误删传播（已用 send-only 杜绝） | **用户手动操作，无自动传播风险** |

**设计红线**：PlainApp 通道**永不接入自动同步逻辑**——它是"手动直连文件服务"，不参与任何自动复制/镜像/删除传播。自动同步只走 Syncthing 一条路（防误删的根不变）。上传方向建议在引导页提示"重要文件请同时走 Syncthing 汇聚"，避免用户以为拖上去就自动同步了。

## 5. 安全

| 项 | 结论 | 说明 |
|---|---|---|
| PlainApp 服务鉴权 | <!-- 待调研填充：有无 PIN/访问码 --> | 若默认无鉴权，信任边界 = 网络层 |
| 电脑 → 手机方向 | **出站连接，无需防火墙规则** | 电脑访问手机是客户端出站，Windows 防火墙不管出站；手机侧 Web 服务监听由 PlainApp 自己放行（安卓 13+ 需用户授权"本地网络"权限，引导页提示） |

| Tailscale 访问 | 推荐主路径：手机装 Tailscale App，地址恒定（100.x.x.x），全链路加密 | 出公网/跨地域也能访问，不受家庭 NAT 限制 |
| 数据平面 | 面板不代理文件流量，浏览器 ↔ 手机直连 | 符合"控制面不碰数据"；面板只见元数据 |
| 风险提示 | 引导页注明：PlainApp Web 服务是"网络直读手机存储"，**只在需要时打开发射**，用完关闭；公共 WiFi 场景禁用局域网路径 | 简单可执行的默认安全习惯 |

## 6. 保活（安卓 16）

> PlainApp 是前台服务应用；安卓 16 的厂商 ROM（小米 HyperOS / 华为 EMUI / OPPO ColorOS / vivo OriginOS / 荣耀 MagicOS）各有后台限制。先给通用条目，分厂商路径由 onboarding 保活清单持续维护（对应 W10 ROM 保活矩阵）。

**通用保活清单（引导页折叠区）**：
1. **电池优化豁免**：设置 → 应用 → PlainApp → 电池 → 选择"无限制/不优化"（厂商路径各异）；
2. **自启动**：设置 → 应用管理 → PlainApp → 允许自启动；
3. **后台活动**：应用信息 → 耗电管理 → 允许后台运行/后台高耗电；
4. **锁定任务**：最近任务界面长按 PlainApp 卡片 → 锁定（防一键清理误杀）；
5. **通知**：保持通知可见（部分 ROM 用"媒体通知保活"，杀掉通知即杀进程）；
6. **省电模式**：系统省电/超级省电模式会冻结后台，使用期间建议关闭。

**预期管理**（沿用技术计划风险 1 的写法）：手机按需在线即可，Web 服务**打开"发射"才监听**——保活目标是"App 不被杀、随时能打开发射"，不是"服务 7×24 常驻"。手机不是服务器。
