## 1. 现状概要（技术实现）

- **架构**：单文件 `index.html`（HTML+CSS+JS 全内联），12 个视图 `<section class="view">`，JS 切换 `display`。iframe 嵌入 3 个第三方服务（alist/Jellyfin/Immich）。终端用 xterm.js。
- **主题**：`<html data-theme>` + 两套 CSS 变量（L9-20），默认深色，localStorage 记忆（`fcp-theme`，L628-632）。变量化彻底：背景/面板/边框/文字/强调/语义色/覆盖层共 13 个 token。
- **调色板**：深色 `bg #0f1115 / panel #15181e / accent #4c9aff`，浅色 `bg #f3f5f8 / accent #2563eb`——冷灰蓝 + 单一蓝强调，与源站 palette 同族（浅色 accent 恰为源站 `#2563eb`）。语义色 ok/warn/err 两套。
- **字体**：系统栈 `-apple-system,Segoe UI,Roboto,…`（L22），无中文字体显式声明（Windows 中文落到系统默认）。字号约 15 档（.64–1.3rem），字重 400/500/600/700 混用。
- **间距**：rem 为主、值域散乱（.42–1.4rem 约 20 个不同值）；圆角 6/7/8/9/10/12px 六档。
- **深色实现方式**：CSS 变量（无 `body[data-theme]` 逐类覆盖），机制上优于源站的逐元素覆盖——天然无全局 fallback 漏网。裸色硬编码仅 4 处，均为功能需要（§4.4）。
- **移动端**：899px 单断点（L204-241）：侧栏隐藏→固定顶栏+汉堡菜单，`main` 内边距缩小，tiles 变 auto-fit 96px，行列表 wrap，按钮 min-height 40px。无 599px 二级断点。
- **编辑模式 UI**：读取时不存在（并行 Agent 一期尚未落盘或未合并）。
- **文案整体质量**：明显高于一般面板——有实测数字、时长预期、后果说明、可操作空态（详见 §2 符合项）。

## 4. 特别关注项详查

### 4.1 总览页图标区（用户刚要求：等宽等高）

- **现状：达标**。`.tiles` 为 7 列 `minmax(0,1fr)` 网格 + `min-height:58px`（L43-44），内容水平垂直居中，`gap:.5rem` 均匀。
- 细节注意：① 375px 下变 3 列 3 行（见 P1-7）；② 第 4-6 项是状态灯（`<i>` 圆点 + 文字），第 1-3、7 项是按钮/数值，同网格但语义不同——hover 时状态灯也有边框变蓝的假可点感（L45 `.tile:hover`），建议状态灯去掉 hover 反馈（或加 `cursor:default`）。

### 4.2 顶栏按钮区（"只在首页显示"）

- **现状：全视图显示**（`.top` 位于 `main` 直接子级、12 个 `.view` 之外，L272-284）。用户预期是只在总览页显示 → 见 P0-2。若确认产品意图为"全局工具条"，则需在宪法登记为有意设计（本文档按"仅总览"处理，因任务描述如此）。

### 4.3 12 视图视觉一致性

- **强一致性**：面板/行/按钮/卡片 token 全站统一；iframes 三页结构镜像（phead+frame-w+覆盖层三态）。
- **不一致点**：① 同步页无数据（P0-1，最严重）；② phead emoji 有无不一（P1-3）；③ 手机接入页用 `.sno` 数字徽章（L169）与步骤条 `.pstep`，为全站独有模式（合理，但样式与 `.metric`/`.svc` 徽章体系不一致）；④ 总览 `.metric` 卡与容器页 `.sw` 卡同为状态卡，间距/内距不同（.6rem/.75rem vs .55rem/.7rem）；⑤ 错误态文案详略不一（P1-6）。

### 4.4 深色模式漏网检查（裸 #fff/#000 硬编码）

全文件仅 4 处裸色，**全部有功能理由**（无漏网）：

| 位置 | 值 | 用途 | 判定 |
|---|---|---|---|
| L170 `.qrbox` | `#fff` | 二维码必须白底 | 允许（建议注释 + 归入功能例外清单） |
| L147/L150/L198-201 | `#0b0e14` | 全屏媒体背景 / 终端恒黑底（有注释 L196-197） | 允许（有意设计） |
| L155 `.fs-exit` | `rgba(15,17,21,.78)` | 全屏态悬浮按钮，压在任何主题之上 | 允许 |
| L44/L83/L216 阴影 | `rgba(0,0,0,.15/.45)` | 阴影硬编码 | 非漏网但建议变量化（P2-1/2） |

结论：**深色模式覆盖无遗漏、无白底黑字风险**，机制（变量双套）值得作为范本写进宪法。

### 4.5 移动端 375px 体验

- **良好**：899px 断点（顶栏+汉堡+下拉）、行列表 wrap（L231-233）、按钮 40px 触摸高度（L234）、二维码自适应 `min(78vw,232px)`（L175）、iframe 56vh、网格降单列。
- **问题**：① tiles 3 行占首屏（P1-7）；② `.rn` 84px + 弹性区换行后行高膨胀可接受；③ `.sn-devices` 在 375px 是 2 列（`1fr 1fr`，L228），卡片内 `.d` 内容长会两行挤——建议 375px 下随 `.snf-grid` 一并降 1 列；④ 无 599px 二级断点，更小屏（320px）未验证。

## 5. 优先级结论与建议实施顺序

1. **立即（P0）**：修同步页死页（P0-1）——这是唯一"用户可见的假页面"；顶栏 tiles 仅总览显示（P0-2）——消除 12 个视图的视觉噪音。
2. **随"组件可编辑系统一期"顺带（P1）**：字号/字重/间距刻度收敛（P1-1/2/10）与 phead 层级（P1-9）最适合在做组件系统时一并 token 化，避免二期之后返工。
3. **近期（P1）**：文案第二人称（P1-5）、错误态统一（P1-6）、状态点统一（P1-4）、移动端 tiles（P1-7）、固定值注释（P1-8）。
4. **积攒（P2）**：阴影变量化、毛玻璃覆盖层、reduced-motion、focus-visible、theme-color meta、emoji 单色化中期评估。

**总体评价**：FlyGo 现状已自发觉察并实现了灵魂的绝大部分（冷色+单强调、语义色职责、变量化深色、真实预期文案、三态齐全、危险确认），主要差距在**刻度纪律**（字号/间距/字重/圆角值域过散）与**两处产品级问题**（同步页死页、顶栏区全视图显示）。修完 P0 与 P1，即可对标源站的完成度。
